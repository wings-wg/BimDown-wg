# BimEditor 面积测算与分摊

面积侧栏运行在本地 BimEditor 实例中。用户从二维模型选取房间，也可以导入原有的 `project-config.json`。计算在浏览器中复用 CLI 的 [模型证据绑定](../../cli/src/area/project-input.ts) 和 [面积算法](../../cli/src/area/index.ts)。原版编辑器的模型打开、二维和三维功能由上游提供。

## 启动

在 BimDown 仓库根目录执行。已有 `.bimeditor-local` 时跳过克隆与切换版本。使用 Node.js 24 运行。

```powershell
git clone https://github.com/NovaShang/BimEditor.git .bimeditor-local
git -C .bimeditor-local checkout --detach f0c2e2386bce098484026ac093c3f30f7b95b3b3
npm install
npm --prefix .bimeditor-local install
node web/area/setup.mjs
npm --prefix .bimeditor-local run dev --workspace=app
```

用 Chrome 或 Edge 打开终端提示的本地地址，默认是 `http://localhost:5174`。更新面积侧栏或共享算法后，再运行一次 `node web/area/setup.mjs`。该命令将跟踪的集成源码复制到忽略的本地上游检出目录。生产构建使用 `npm --prefix .bimeditor-local run build --workspace=app`。

开发服务器检测到共享编辑器源码变更时会刷新整页。刷新后，从首页重新打开项目。更新前可将内存中的 ZIP 项目下载或保存到文件夹，以保留会话内的编辑。打开本地目录时，选择包含 `global/level.csv` 的项目根目录，页面会显示楼层读取状态。

## 使用

1. 在首页打开本地项目目录、Revit 导出的 `.bimdown` 包或 `.zip` 包。先试运行时，可使用首页的样例入口。
2. 打开右上角的 **面积测算与分摊**。项目原有的面积配置会自动读取。可导入已有配置、按入户门归户或手动按房间归户。
3. 在 **共用区域** 逐间确认分摊住户、方法、计入系数和审核依据，再保存。显式权重、补充测量分项、多种计入部位、自动系数条件与独立幢总量可在 **配置 JSON** 中维护。
4. 缺少房间轮廓时，在 **测算轮廓** 中选择楼层范围并生成。填写 **测算规则来源**，例如本次采用的测算文件或审核记录。核对轮廓边界、归属和分摊范围，勾选审核确认并运行测算。样例应显示套内 80 m²、分摊 20 m²、合计 100 m²。点击结果中的模型分项可定位房间。下载的配置与报告使用 CLI 格式。

测算支持现有 `area-project` 契约中的 BIMDown GeoJSON v2 及其单位。几何文件、测算配置与报告保留在本地浏览器或用户选择的本地位置。实际项目的边界、共有归属和计入系数仍由审核人确认。

## 保存并继续操作

- **从本地文件夹打开**时，确认归户、保存分摊或删除户后，网页自动把户号、房间归属、计入系数和分摊规则写入项目根目录的 `project-config.json`。看到 **归户及分摊配置已保存到项目文件夹** 后，可关闭页面。重新打开同一目录，即可在 **已归户** 和 **共用区域** 继续操作。
- **从 ZIP 或 .bimdown 打开**时，配置随当前项目草稿更新。关闭前点击右上角的 **ZIP** 下载更新后的压缩包，或点文件夹图标 **保存到文件夹**。下次打开保存后的项目。
- 直接编辑 **配置 JSON** 后，点击 **保存配置** 提交。也可点击 **下载配置** 单独备份，在需要时用 **导入配置** 恢复。若自动保存失败，面板会显示原因，可重试保存。
- 重新打开后，运行测算前须再次勾选审核确认。

## 按入户门归户

1. 在当前楼层的二维平面上选中一樘入户门，在面积侧栏展开 **按入户门归户**，保持 **连通依据** 为 **当前平面（含网页新建房间）**，填写户号并点击 **预览户内房间**。
2. 若门两侧都有候选，从 **选择户内一侧** 选取入户后的第一个房间。可点击预览列表里的房间，在平面上定位并核对范围，再点 **确认批量归户**。当前平面模式根据门的宿主墙、门位置和同层房间边界推断连通性，遍历遇到配置为共有或排除的房间时停止。若两侧仍经其他门相通，页面会提示核对户界。请核查预览房间是否包含公共走廊或相邻住户的房间。
3. 新增分项暂用计入系数 1。房间缺少可测算轮廓时仍可保存归户草稿，测算前在 **测算轮廓** 中补齐并审核。
4. 归户后，在下方 **已归户** 列表点击户号。平面会选中并高亮该户在所在楼层的全部房间，视图会缩放到这些房间。跨层户可用户号下方的楼层按钮查看各层。导入已有归户配置后，也可直接点击列表中的户号。

**已归户** 在首次归户前也会显示空列表。点击 **确认批量归户** 时，页面会提示当前需要预览、选择户内侧或填写户号；确认成功后会滚动到户列表。

已有完整 Revit 房间证据时，可将连通依据切换为 **Revit 导出证据**，使用 `area_features.json` 和能唯一对应楼层、短 ID、UUID 的 `_IdMap.csv`。这一模式会使用 Revit 标记的公共房间和户界门。旧导出包的跨层短 ID 若有歧义，用新版插件重新导出门和房间。可选参数见 [Revit 面积证据说明](../../revit-addin/Area/README.md)。

打开内置面积样例后保持空白配置，选择公共走廊与客厅之间的门 `d-1`，填写 `101`，预览时选择客厅一侧并确认。预览应包含客厅和卧室。填写测算规则来源并审核后，示例套内面积为 104 m²。

## 按房间归户

打开目标楼层，展开 **按房间归户**。可以按房间名称或 ID 搜索和勾选，多个名称可用逗号分隔。也可以在二维平面用 Shift 多选，再点 **使用图中选中的房间**。填写目标户号后点 **确认按房间归户**，并在 **已归户** 中核对房间数量。

已有归属的房间须确认改归。改归逐房间设置过共用分摊的房间时，会同时移除该房间的分摊规则。传统共有池中有分摊依赖的房间须在配置 JSON 中核对。房间归户后会从共用区域中移除。

## 删除房间或户

- 在可编辑楼层的 **按房间归户** 中勾选一个或多个房间，点击 **删除所选房间** 并确认。模型中的房间、对应的已生成轮廓和测算配置会同步清理。编辑器的 **撤销** 可恢复模型房间，恢复后需补齐轮廓并重新设置归户和分摊。
- 在 **已归户** 中点击户号右侧的 **删除** 并确认。原房间保留在模型中并解除归户。分摊规则会移除该户。没有其他接收户的共用房间回到 **待设置**。核对更新后的分摊和保存状态。

## 按共用房间分摊

归户楼层中尚无归属的房间默认列入 **共用区域**。可勾选一个或多个共用房间，也可点击 **全选本层待设置**。选择按自身计入面积比例或等份，填写分摊依据，再点击 **保存本房间分摊** 或 **批量保存分摊**。

初次设置分摊时，需确认接收户、计入系数和边界审核依据，每个房间仍有独立的测算分项和共有池。批量编辑已设置的房间时，统一更新分摊方式和分摊依据，各房间保留自己的接收户、计入系数和边界依据。要修改这些字段，可只勾选一个房间。

未保存分摊规则的房间会显示为 **待设置**，当前测算结果和下载报告会标明待设置范围。所有已保存的分项都需要可审核的测算轮廓。导入的传统共有池仍可使用 **已有共有池分摊** 和 **配置 JSON**。

## 自动创建房间

1. 在 **面积测算与分摊 → 自动创建房间** 选择 **当前楼层** 或 **全部楼层**，点击 **识别闭合房间**。网页使用墙、结构墙、幕墙及房间分隔线识别闭合区域，跳过已有房间占据的区域。
2. 核对预览的定位点和面积，取消勾选管井等不应创建房间的区域，然后点击 **创建所选房间**。编辑器按楼层标高由低到高、同层按平面从上到下再从左到右创建。房间名称如 `F1-room1`、`F1-room2`、`F2-room3`，编号在整个项目中延续。已有房间保留原名。
3. 新建房间按编辑器惯例保存到相应楼层的 `space.csv`，整批可以一次撤销。打开本地文件夹时使用编辑器的自动保存，打开压缩包时可下载编辑后的 ZIP。

预览显示墙面之间的计算面积，无法计算墙面内轮廓的区域标注为墙中心线面积。几何候选可能包含公共区域，测算口径和归属仍需审核。批量创建的房间种子点可通过 **当前平面** 模式按门归户。

## 生成测算轮廓

1. 打开可编辑楼层，展开 **面积测算与分摊 → 测算轮廓**。选择 **当前楼层** 或 **全部楼层**，点击 **生成测算轮廓**。
2. 网页根据已有房间的定位点匹配闭合墙线，沿墙中心线补齐该楼层的 `space.geojson`，保留已有轮廓。界面列出待核对的房间，可点击名称在平面定位。常见情况包括墙线未闭合、同一围合区域有多个房间及轮廓嵌套。
3. 在本地文件夹模式下，生成的轮廓保存到项目。通过 ZIP 或 `.bimdown` 打开时，请下载更新后的 ZIP 或保存到文件夹，以便下次继续。
4. 核对测算边界并重新勾选审核确认，再点击 **运行测算**。测算按轮廓多边形计算面积，平面图通常显示墙面之间的净面积。若修改墙线后需要重算已有轮廓，可在项目工作副本运行 `bimdown build`，再核对输出。

## 导出模型显示

新版 Revit 插件导出的房间可能已带有 `space.geojson` 完成面轮廓。使用已有轮廓测算前，请核对它是否符合本次选用的测量边界。页面的补齐轮廓操作保留已有文件中的房间轮廓。 [Revit 工程证据说明](../../revit-addin/README.md#工程证据导出)

安装脚本会修正 Windows 检出时的三维 HDR 资源，并让缺少宽度的门窗使用编辑器已有的显示尺寸计算视图范围。显示尺寸仅用于可视化，测算仍使用项目中可复核的几何证据。

在二维视图左侧选择楼层后，点击顶部 **3D**，即可查看该层的三维模型。也可以右键目标楼层，选择 **仅显示该层**，直接进入三维。单层模式下点击另一楼层会切换到该层。右键选择 **显示所有楼层**，或在三维视图左下角的楼层下拉框选择 **全部**，即可恢复整栋显示。

## 上海 2022 版单幢房产面积

1. 打开 BIMDown 目录或压缩包，在 **面积测算与分摊** 中展开 **上海 2022 版单幢房产面积**。
2. 点击 **读取项目房产证据** 加载根目录的 `property_area.json`，也可 **导入复核证据** 或按当前项目版本生成证据草稿。录入独立核定的幢总面积、各户套内分项、独立使用空间等扣除项、共有台账和全幢受益对象。
3. 填写复核依据并勾选确认，点击 **运行单幢差额法**。缺少必要证据时，页面列出待补字段。按入户门归户和自动创建房间可为核对套界提供线索，采用面积需依据已复核的产权边界。
4. 查看每户套内建筑面积、共有分摊、套建筑面积与套内分项来源，下载复核证据和完整报告。证据可再次导入继续操作。 [计算口径与 CLI 复算](../../cli/src/area/README.md#上海-2022-版单幢房产面积)

模型还缺专项证据时，可先点击 **从当前模型提取候选证据**。选择标高层查看楼板及屋面投影、按宿主扣洞后的投影和房间覆盖情况，也可点击来源编号定位构件。点击 **下载模型候选证据** 保存逐层 JSON。候选投影用于辅助核对边界，复算仍从已审核的专项证据读取采用值。 [离线取证命令与口径](../../cli/src/area/README.md#从导出模型提取候选证据)

网页已创建房间时，打开 **逐间查看面积与边界** 可查看每间房的候选面积和边界口径。即使项目只有房间定位点，取证也可沿墙线推导轮廓。待核项可点击房间名称定位。需要把轮廓保存供现有归户和面积工作流使用时，可在 **测算轮廓** 点击 **生成测算轮廓**，保存后重新提取候选证据。

## 模型核查

模型打开后，也可以在「输入自然语言条款」粘贴一条完整要求并点击「编译文本条款」。文本与 Excel 共用编译、验证、审核和执行流程，原文保留在报告中，并生成稳定的条款编号。底部问答或面积入口识别出核查要求时，可以把原文填入核查侧栏，再由用户提交。

1. 打开 BIMDown 模型，点击右上角 **模型核查**，上传 `.xlsx` 条款表或已审核的 `.json` 规则包。Excel 优先读取「强条规则表」，也可使用带「条款编号」「条款正文」的自定义工作表。判定条件、限值和适用范围明确的住宅层高下限可在本地解析。其余条款点击 **PAL 编译**，分批将条款字段发送给「模型设置」配置的服务。模型文件和核查证据在本机使用。JSON 沿用 [独立标量规则包](../../cli/src/engineering/README.md#独立规则包与证据清单) 的格式，可离线执行。
2. 阅读可执行条款和来源。网页从 `global/level.csv` 预填建筑标高配对候选，优先使用适用的导出配对，否则选最近且唯一的更高标高。可改选上方标高，或选择「手动填写层高」并填写米值和依据。屋面标高点可以成为上方参考，本身保留「待确认」，可手工标记不适用。多个层高条款在同次运行中使用相同楼层适用范围。
3. 对照原文确认生成的规则。可取消某条候选的「纳入核查」。Excel 条款勾选审核确认后自动运行。修改证据或使用 JSON 规则包时可点 **运行已就绪条款**。结果的「无法判断」统计对象记录，「待处理条款」单列编译、工具和审核缺口。结果可筛选和下载，不通过项可定位楼层或房间。可下载已审核规则包，后续直接上传 JSON 重跑。

PAL 根据原文生成受约束的规则结构。程序检查工具、范围、数值引用和单位，模型返回的程序或合规结论不进入核查。当前工具支持建筑层高（如 JT-01）、模型记载房间净面积和房间净高局部例外（如 JT-02）。条款支持范围仍取决于现有证据和工具；不支持、含义不清或数值无法核对时，报告保留原文位置与缺口。核查报告记录编译模型、方案及审核状态。JSON 标量规则包支持下列概念：

| `targetTable` | `concept` | `unit` | 模型证据 |
| --- | --- | --- | --- |
| `level` | `storey.architectural-height` | `m` | 已确认的两个 `global/level.csv` 标高之差，或用户填写的建筑层高和依据 |
| `space` | `space.model-recorded-net-area` | `m2` | 唯一房间轮廓的 `space.geojson` 的 `net_area`，适用范围须确认为模型全部房间 |

模型应在 `project_metadata.json` 中声明坐标单位。缺少标高、缺少净面积记录、重复轮廓或未经确认的适用性都会保留原因。房间净面积采用模型记载的口径。核查在浏览器本机执行，报告使用读取的模型证据指纹和条款来源追溯。规范适用性需按项目复核。

### 导出建议与 PAL 工具库

核查报告中的 **工程证据预检** 显示同一导出版本的 Revit 观测、已确认量测与适用性记录数量。待核定对象可直接定位。候选标高差、名义板厚、名义门宽和 Revit 房间面积作为来源线索，只有满足对应口径的审核记录才能用于核查。导出建议按缺对象、缺量测、适用性待确认等原因汇总，同一对象可能有多项待办。

**导入 Codex 候选包**需先打开原工作簿。下载待处理条款模板，把 Codex 生成的声明式方案放进各条 `proposal`，保留模板的 `clause` 和 `source`。工具方案使用 PAL 的 `tool-draft` 格式，`verification` 填本机固定用例的通过名称，可由 `verifyToolRecipe` 复算。标量等无需工具的方案保留空验证列表。每包最多 20 条和 64 KB。导入会逐条验证原文、限值、配方及验证记录，刷新工具库，保留当前模型、审核录入与既有报告。新工具需独立审核启用，新方案需纳入下一次条款审核。

**条款追踪**可核对工作表原文、计划和状态。结果可同时按条款和判定状态筛选，也可定位具体楼层或构件。下载的核查报告保留完整结果、原表追踪、工具版本及当前筛选条件。

**补证据与复跑**可在旧报告中保存并下载基线，按导出建议更新项目证据。在同一页面刷新模型证据，或重新打开模型和同一条款文件后读取基线，再确认规则并点击 **复跑受影响条款**。报告保留两次模型快照、证据版本和匹配到相同作用域对象的状态变化。只对比本次执行的条款。

1. 用 Excel 做 **PAL 编译** 时，系统先把已启用工具及测量口径交给 PAL。找不到能表达条款的已启用工具时，PAL 可以用已注册的读取或同测点高程差原语生成候选。候选、来源模型、触发条款和验证记录保存在本地工具库；同一测量口径和运算组合不会重复建立版本 1。条款阈值独立于工具。
2. 在 **PAL 工具库** 检查候选的测量口径、输入与验证结果，再选 **审核并启用工具**。服务端重跑固定用例后才启用；以后重新编译会复用。工具库在编辑器服务目录的 `.data/pal-tool-library.json`，服务重启后仍可使用。已审核 JSON 规则包也可引用已启用的同一工具 ID。
3. 审核并运行条款后，在 **BIMDown 导出建议** 查看缺证据的规则、文件、字段、量测口径和适用性绑定。下载的核查报告含相同建议和每项结果所用工具版本。未能用现有原语表达、条款不明确或缺外部依据的条目留在待处理区。

工具库目前支持现浇实心楼板的有效结构层厚、房间完成面最低净高和门开启后的有效通行净宽。模型核查还支持四类门的净宽分档和已确认上下层房间的二维投影叠合。生成的是受约束的工具配方，项目数据及条款适用性由工程人员审核。Revit 插件目前不会自动输出以下工程证据。

为启用的工具补证据时，模型保持原有逐楼层对象 CSV。在项目根目录补 `engineering_evidence.json`，并在 `project_metadata.json` 声明同一份导出的 `engineering_revision`。以下为读取已确认结构层厚度的合成例子；将 ID、规则版本、适用正文和来源替换为本次报告中的内容。若工具使用结构层顶底高程差，改为导出 `slab.structural-top-elevation` 与 `slab.structural-bottom-elevation` 两份量测，它们须有相同、非空的 `measurementGroup`，表示同测点与高程基准。

```json
{
  "version": 1,
  "modelRevision": "example-export-1",
  "measurements": [
    {
      "object": { "scope": "lv-2", "table": "structure_slab", "id": "ss-1" },
      "concept": "slab.cast-in-place-solid-structural-thickness",
      "value": 120, "unit": "mm", "confirmed": true,
      "source": "已审核的结构剖面 S-01"
    }
  ],
  "applicability": [
    {
      "object": { "scope": "lv-2", "table": "structure_slab", "id": "ss-1" },
      "ruleId": "JG-03", "ruleVersion": "pal-1",
      "applicability": "适用范围正文",
      "decision": "applies", "source": "已复核板型与结构层口径"
    }
  ]
}
```

同一对象缺少适用性、单位不符、引用重复或证据与模型版本不匹配时，结果为无法判断。板表的名义 `thickness` 和门表的 `width` 不参与这些专业口径的判定。见 [工程证据格式](../../spec/engineering_evidence.schema.yaml)。

### JT-02 房间净高

上传规则表后，在 **房间净高证据** 展开目标房间。确认它属于本款适用的普通卧室或起居室，再填最低完成面净高、室内使用面积、净高低于表中常规限值的面积及证据来源。三个量分别以 m、m²、m² 填写，面积按同一使用面积边界计量。案例可填最低 2.20 m、使用面积 12 m²、低于 2.60 m 的面积 4 m²，边界通过；面积改为 4.01 m² 或最低改为 2.19 m 时，结果分别说明超比例或低于局部下限。点击不通过项的 **定位房间** 可回到对应平面。

净高证据需要来自完成地面至上方限制面的测量或经复核的净高分析，网页当前从模型读取房间清单。缺少证据和待确认房间保留为无法判断。坡屋顶房间从本款排除，按 GB 55038-2025 第 4.1.2 条第 3 款另行核查；本原型针对第 2 款。 [GB 55038-2025](https://ghzrzyw.beijing.gov.cn/biaozhunguanli/bzzl/202506/P020250609570099619169.pdf)

同类型的已审核 JSON 规则可在 `rules` 中提供 `kind: "clear-height-with-local-exception"`，使用同样的 `id`、`version`、`reviewed`、`source`、`applicability` 字段，并声明以米计的 `nominalHeight`、`minimumHeight` 及 `maxLowAreaFraction: { numerator, denominator }`。低净高面积按该规则的常规限值录入，换限值时须有与新限值对应的面积证据。

也可以在工程证据文件里提供已确认的最低净高量测、规则适用性和 `clearHeightAreas` 记录。须注明低净高面积对应的限值、使用面积、共用面积边界和来源。网页中实际保存的人工录入可单独用于该房间的核查。

### JT-08 跨层投影与 JT-12 门净宽

- JT-08 使用 `spaceRelations` 的已确认上下层配对、用途、公共坐标系及下层清单完整性。待核查房间按 `space.csv` 的作用域 ID 选择 `space.geojson` 的闭合轮廓。结果记录相交面积与几何，可定位上下层房间。轮廓带洞，或者两者仅边界接触时，计算按二维投影的正面积判定。
- JT-12 将原文四档限值分别绑定到户门、居室门、厨房门和卫生间门。需启用门有效通行净宽工具，并补齐 `doorUses` 的用途、开启角与测线及逐对象适用性。量测值及来源从同版本工程证据文件读取。

这两种计划与已审核规则包均可使用。缺少适用性、有效轮廓、用途或量测等必要证据时，报告保留缺口与补导建议。离线验证方法见 [PAL 合成回放](../../research/benchmarks/pal-offline.md)。

## 模型问答

配置语言模型后，在页面底部的 **模型问答** 用自己的话提出要求。LLM 先判断是执行操作、查询模型还是需要澄清。「能不能把 F1 给我平面铺开看一下？」可打开 F1 的二维平面图，「F1 有多少房间？」会查询模型证据。程序验证返回的操作和参数，指定楼层须能从本轮输入和当前项目中定位。修改模型的流程保留表中的预览或确认步骤。

输入「可用命令」可以查看功能示例。未配置模型时，可使用本地示例命令和证据查询。已配置的模型暂时无法识别意图时，网页转入模型证据查询。

| 网页功能 | 可输入的示例 | 网页响应 |
| --- | --- | --- |
| 视图与楼层 | `切换到3D视图`、`返回2D视图`、`显示F1的2D视图`、`只显示当前楼层`、`切换到F2`、`下一层` | 切换视图或显示范围，也可直接打开指定楼层的平面图。找不到楼层或有多个匹配时会给出提示 |
| 缩放、平面显示与选择 | `放大当前视图`、`缩小当前视图`、`全图显示`、`显示网格`、`隐藏构件编号`、`打开小地图`、`取消选择` | 2D 和 3D 模型视图均可逐档缩放，平面可全图显示或调整显示选项，也可清除选中对象 |
| 编辑历史 | `撤销上一步`、`重做上一步` | 调用编辑器的撤销或重做 |
| 房间创建 | `在所有楼层自动创建房间`、`在当前楼层自动创建房间` | 预览候选房间。核对范围和候选区域后点击「创建所选房间」，整批可撤销 |
| 面积测算与分摊 | `打开面积测算与分摊`、`运行面积测算`、`给当前楼层生成测算轮廓`、`给所有楼层生成测算轮廓` | 按已审核配置运行测算。生成测算轮廓前，在面积面板确认写入范围 |
| 房间归户与共用面积 | `按入户门归户`、`按房间归户`、`设置共用房间分摊` | 打开原流程。当前已选中入户门时可准备归户预览 |
| 模型核查 | `打开模型核查`、`运行模型核查` | 使用面板中已上传并审核的条款运行。结果定位和补导建议显示在核查面板 |
| 删除构件 | `删除选中的构件`、`删除 d-1`、`删除本层全部门` | 问答会在当前楼层匹配对象，列出目标后要求确认。也可直接在底部工具栏删除已选对象，删除可撤销 |
| 软件改进 | `打开功能建议` | 打开功能建议表单 |

模型问答默认使用当前楼层，可在问题里指定楼层和房间编号，或在平面上选中构件后提问。试问「F1-room3 的轮廓面积和归属是什么」「本层有多少扇门」「101 户分摊多少」。查询分户结果前，先在面积侧栏核对并运行测算。

**模型证据** 显示取数来源和作用域，可点击 **定位** 查看对象。问答可引用几何轮廓面积、模型记录的净面积、墙体的标高与高度、归户配置和本次测算结果。净高、顶盖或全高围护缺少几何测量时，会提示证据范围。

配置语言模型后，模型分析也可选择只读量测工具。对已注册口径的量测，问答搜索与核查共用的工具库。没有启用工具时，PAL 可用固定原语生成候选配方，保存后可在「审核 PAL 工具」中确认口径并启用。再次提问时，用明确的楼层和构件 ID，或在平面图选中构件。量测工具核对当前模型版本、构件作用域和已确认的测量字段。缺少证据时，「模型证据」列出建议补导的文件和字段。

新增对话操作时，在同一命令表登记语义、参数与示例，并连接现有的编辑器动作或工作区流程。本地匹配用于离线入口，帮助列表、PAL 提示和参数验证读取命令表。[命令表](editor-commands.ts) · [工作区调用](ModelQuestionPanel.tsx)

### 在网页配置云端模型

1. 在 **模型问答** 旁点击 **模型设置**。
2. 选择 DeepSeek、OpenAI 或阿里云百炼（北京按量付费）。确认模型名并填写该服务的 API 密钥。DeepSeek 默认关闭思考模式，可在设置中开启。
3. 点击 **测试连接**。测试只向所选服务发送一条固定消息，成功后点击 **保存并启用**，配置立即生效。

启用后，用户输入会发送到输入框下方显示的服务地址，用于识别意图。回答模型数据问题时才会发送匹配的模型证据。浏览器标签页只保存会话标识，密钥保存在本地网页服务的内存里。刷新同一标签页可继续使用，保存后满 12 小时或服务重启后需重新输入密钥。可点击 **切回服务端默认** 清除当前会话的云端设置。

### 配置服务端默认模型

本地模型、自定义服务和阿里云百炼的其他地域可通过服务端配置接入。兼容接口为 `chat/completions`。将下列设置写入本地编辑器的 `.bimeditor-local/app/.env.local`，或在启动前设置同名环境变量。以已经运行的本地 Ollama 服务为例，将模型名替换为实际已安装的标签。 [Ollama 接口文档](https://docs.ollama.com/api/openai-compatibility)

```dotenv
BIMDOWN_QA_URL=http://127.0.0.1:11434/v1/chat/completions
BIMDOWN_QA_MODEL=实际已安装的模型名
# 服务要求鉴权时填写 BIMDOWN_QA_API_KEY
```

重启本地网页服务使配置生效。开发和预览服务器均提供问答接口，密钥只在服务端读取。提问时先发送问题生成计划，有证据时再发送匹配证据生成回答。接收地址显示在输入框下方。未配置语言模型时，页面仍可显示本地查询证据。

## 自然语言测算计划

在「面积测算与分摊」展开「用自然语言制定测算计划」。可以输入「按现有配置测算全项目面积并分摊」或「给当前楼层生成测算轮廓」。面积分摊沿用项目当前配置和人工审核，轮廓计划显示将保存轮廓的楼层范围，确认后调用现有几何工具。缺失模型单位或轮廓文件时，测算提示需要补导的证据。计划编译只发送用户输入的要求。

## 将功能建议交给 coding agent

在项目页点击「功能建议」，填写模块、当前行为和复现步骤、期望行为、验收标准，可附需要保留的行为或约束。点击「下载开发任务」后，得到带版本的 `bimdown-development-request.json`。可以在 BIMDown 的 coding agent 会话中附上文件，请 agent 完成开发与验证。

也可以从仓库根目录用 Node.js 24 预览任务，再用本机已登录的 Codex CLI 执行。为执行指定包含所需基线的干净 BIMDown 检出目录，建议使用单独的工作树。运行后可在该工作目录检查代码差异和验证结果。

```sh
node scripts/run-coding-request.mjs /path/to/bimdown-development-request.json --preview
node scripts/run-coding-request.mjs /path/to/bimdown-development-request.json --run /path/to/bimdown-worktree
```

网页生成开发任务，仓库操作由显式调用的 coding agent 执行。工程计划和工具配方仍由原有的验证与审核流程处理。涉及新算法或新界面时，可以通过开发任务实现并测试，再登记受支持的工具或规则口径。
