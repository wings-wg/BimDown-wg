# BIMDown工程数据表达、PAL可验证计算与受控自进化

## 目标

研究如何用BIMDown表达可复算的工程证据，如何用PAL将自然语言工程要求转为可验证的计算，以及如何利用运行反馈持续扩充数据、工具和程序。确定性算法负责计算，专业审核负责确认关键工程口径。

## 三项研究与开发方向

| 方向 | 研究问题 | 后续开发产出 |
|---|---|---|
| BIMDown工程数据表达 | 怎样表达构件、几何、属性、关系以及测量口径、单位、来源和模型版本，使工程事实可读取、复算和追溯？ | 版本化的BIMDown工程证据契约、兼容适配、导出和复算样例 |
| PAL自然语言转换与可验证计算 | 怎样保留工程要求的适用对象、口径、阈值和例外，识别缺失的证据或工具，再执行可复核的计划？ | C1可计算语义、C2可计算性诊断、C3受控执行与证据三个共用模块 |
| 反馈驱动的受控自进化 | 能否将数据、工具和程序缺口转为经验证的更新，提高未见任务的正确执行率，同时控制错误放行和回归？ | 数据补导闭环、受限PAL工具验证入库、带验收标准的coding agent开发任务及多轮评价 |

面积测算与分摊、模型核查、模型问答是三个共用验证场景。开发里程碑、验收门槛及对照实验见路线图，原型的实现和验证范围见状态记录。研究贡献的新颖性需经文献综述和实验确认。

## 示例

安装依赖并在仓库根目录构建后：

```bash
npm install
npm run build --workspace=cli
node cli/dist/cli.js area-project sample_data/area-example/model -c sample_data/area-example/project-config.json -o /tmp/bimdown-area-report.json
```

示例预期：套内80平方米，分摊20平方米，合计100平方米。它验证显式确认输入下的计算链路，不证明自动识别了分户、权属或法定测算边界。命令的完整构建/运行状态见STATUS。

## 范围

以面积分摊、住宅模型核查和模型问答为主案例，后续可用工程量提取或变更影响分析验证迁移能力。专业审核覆盖工程口径、规则适用性和关键证据。工具配方的启用与程序改动的纳入均需经过相应验证和审核。

用户提供的面积PDF及核查Excel为需求材料，未作为公开研究数据集纳入仓库，阈值及条文效力尚未独立核实。后续需建立具有来源和适用版本的规则集及可发布合成案例。
